# v0.1.2

This patch stops a false "deliveries need attention" incident. Delivery attempt
records are written to ClickHouse on a best-effort basis. When that write failed
during a brief connection error, the delivered event had no record, and the
delivery monitor reported it as waiting for up to seven days.

Two changes close the gap. The shared ClickHouse insert helper now retries a
transport error, 429, or 5xx response twice with a short backoff before it
gives up, for both accepted events and delivery attempts. The delivery monitor
also confirms each event that has no attempt record against its delivery claim
in Postgres, and does not count an event whose claim settled as completed.

## Upgrade from v0.1.1

There are no schema migrations or required environment changes in this patch.
The dashboard's existing database role already reads `delivery_idempotency`.
Back up your database before upgrading, then check out the release:

```sh
git fetch --tags
git checkout v0.1.2
```

Set `AXEL_IMAGE_TAG=0.1.2` in your existing `.env.selfhost`, then run:

```sh
./scripts/axel-self-host edge
./scripts/axel-self-host up
```

`edge` deploys the Workers from this checkout, which carry the retrying insert
helper. `up` pulls the versioned images, verifies database setup, and restarts
the containers.

To roll back this patch, check out v0.1.1, restore `AXEL_IMAGE_TAG=0.1.1`, and run
the same two commands. Keep your existing environment file and data volumes.
An incident opened by a lost attempt record under v0.1.1 closes on its own once
the event leaves the seven-day window, or when you acknowledge it.

See [self-hosting](../self-hosting.md) for installation details, or
[create an Axel Cloud account](https://app.axelapp.ai/signup?ref=github).
