# v0.1.1

This patch fixes an authorization failure when a webhook request crosses the
five-minute source cache expiry. Unchanged credentials remain valid through the
refresh. Credential changes and source fences still revoke earlier authorization,
and an origin outage still returns a retryable failure.

Queue metrics now treat an unknown oldest-message timestamp as unavailable.
Axel retains the backlog count without reporting zero lag or raising an exception.
The authenticated delivery metrics endpoint exposes sample and age availability.

Self-hosting images contain only production dependencies and runtime files.
On the same ARM64 Docker installation, migration, dashboard, and delivery images
were 83%, 88%, and 83% smaller than v0.1.0. Images support Linux x86-64 and ARM64.

## Upgrade from v0.1.0

There are no schema migrations or required environment changes in this patch.
Back up your database before upgrading, then check out the release:

```sh
git fetch --tags
git checkout v0.1.1
```

Set `AXEL_IMAGE_TAG=0.1.1` in your existing `.env.selfhost`, then run:

```sh
./scripts/axel-self-host edge
./scripts/axel-self-host up
```

`edge` deploys the Workers from this checkout. `up` pulls the versioned images,
verifies database setup, and restarts the containers. The dashboard reads its
public URLs at startup, as in v0.1.0.

To roll back this patch, check out v0.1.0, restore `AXEL_IMAGE_TAG=0.1.0`, and run
the same two commands. Keep your existing environment file and data volumes.
Rollback does not backfill events a sender failed to retry.

See [self-hosting](../self-hosting.md) for installation details, or
[create an Axel Cloud account](https://app.axelapp.ai/signup?ref=github).
